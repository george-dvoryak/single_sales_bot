# Релей вебхуков Продамуса через Cloudflare Worker

## Зачем

Прямые запросы Продамуса до PythonAnywhere доходят через раз. Замеры из панели Продамуса:

* по **https**: TCP-соединение встаёт за 0.19 с, дальше TLS-рукопожатие получает 0 байт и
  умирает по таймауту (`pretransfer_time=0`, `certinfo` пустой — сертификат не пришёл);
* по **http**: запрос уходит целиком (`size_upload=768`), ответа нет ни байта за 10 с.

При этом наше приложение отвечает за 0.34 с на лёгком запросе и за 1.7–2.0 с на самом тяжёлом,
а подпись и обработка заказа проверены на трёх реальных вебхуках. То есть сломана только
доставка на сетевом уровне между Продамусом (Yandex Cloud, `158.160.25.31`) и PythonAnywhere
(AWS, `35.173.69.207`) — и починить её с нашей стороны нельзя.

Релей подменяет обе ноги пути на рабочие: «Продамус → Cloudflare» и «Cloudflare → PA».

## Разворачивание (дашборд, без CLI)

1. Зарегистрироваться или войти на **dash.cloudflare.com**. Бесплатного плана достаточно —
   100 000 запросов в сутки, карта не нужна.
2. Левое меню → **Workers & Pages** (в новом интерфейсе — **Compute**).
3. **Create** → вкладка **Workers** → **Create Worker**.
4. Имя: `prodamus-relay`. Адрес получится вида
   `https://prodamus-relay.ИМЯ-СУБДОМЕНА.workers.dev` — при первом Worker'е Cloudflare
   попросит выбрать субдомен, запиши его.
5. **Deploy**, затем **Edit code** (либо *Continue to project* → *Edit code*).
6. Выделить в редакторе всё содержимое, удалить, вставить целиком
   [cloudflare-worker.js](cloudflare-worker.js) → **Deploy**.
7. Открыть адрес Worker'а в браузере. Должно ответить:
   `Prodamus relay is alive. Send notifications here via POST.`

## Переключение Продамуса

В настройках payform, блок «URL для уведомлений»:

1. добавить адрес Worker'а;
2. **удалить прямой адрес** `https://ysingle-goshadvoryak.pythonanywhere.com/prodamus_webhook`.

Оба адреса одновременно держать нельзя, пока обработчик не идемпотентен: один и тот же
платёж прилетит дважды, и покупатель получит две инвайт-ссылки, а в `purchases` появятся
две записи.

## Проверка, что релей работает

Переотправить вебхук по любому заказу (иконка ↺ в блоке «URL-уведомления») и посмотреть лог
захвата — токен берётся из `.env`:

```bash
curl -s -H "Authorization: Bearer $(grep WEBHOOK_SECRET_TOKEN ~/single_sales_bot/.env | cut -d= -f2)" "https://ysingle-goshadvoryak.pythonanywhere.com/prodamus_log?n=5&q=X-Relay"
```

В записи должны быть `"X-Relay": "cloudflare-worker"` и `"X-Forwarded-For"` с настоящим
адресом Продамуса. В панели Продамуса статус попытки должен стать успешным.

## Что делает Worker

Пересылает тело **байт в байт** (`arrayBuffer`, без разбора формы — любое перекодирование
сломало бы подпись HMAC) вместе с заголовками `Sign`, `Content-Type`, `Content-Length`,
`User-Agent`. Возвращает Продамусу ровно тот код и тело, что отдало приложение, — иначе
Продамус посчитает доставку неудачной и будет повторять. Если PA недоступен, отдаёт 502,
чтобы Продамус повторил попытку, а не потерял оплату. POST без заголовка `Sign` не
пересылается вовсе — так интернет-сканеры не засоряют лог приложения.

Открытым прокси Worker не является: адрес назначения зашит в код, других он не принимает.
Подлинность запроса по-прежнему проверяет подпись HMAC на нашей стороне — релей ничего
не подписывает и ключа не знает.

## Если не заработает

Значит `*.workers.dev` недоступен из сети Продамуса (бывает из-за блокировок) — в панели
будет тот же таймаут. Тогда варианты:

* привязать к Worker'у свой домен (Cloudflare → Worker → *Settings* → *Domains & Routes*);
* поднять такой же релей в **Yandex Cloud Functions** — Продамус сам ходит из Yandex Cloud
  (`158.160.25.31`), так что связность там заведомо есть.
